## 5. Ambiguities / conflicts & proposed assumptions

a) SPEC doesn't say when `bookings.driver_id` is set → assumption: it holds the driver with the current offer (or last assigned); set on offer, nulled when the offer returns to REQUESTED after decline, kept through CANCELLED/COMPLETED. Non-assigned driver accept → 409.
b) "skipping drivers who timed out" but no pg-boss/webhooks in Phase 1 → assumption: `booking_declines` is the skip list; timeout handling deferred to Phase 3.
c) USSD says HHMM today, SPEC column is `pickupAt` → assumption: DateTime stored; REST accepts ISO string; no timezone dependency (Intl only).
d) `webhook_events` unused in Phase 1 → assumption: table created per SPEC; idempotency enforced in Phase 2+.
e) FakeMessenger writes to `messages` table → assumption: optional Prisma client; memory-only when absent (unit tests), DB row inside the service transaction (acceptance).
f) `CR` + 4 digits = 10k space → assumption: ≤5 collision retries, then error.
